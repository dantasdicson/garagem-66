Resumo executivo

A arquitetura do projeto está alinhada ao documento de visão: React na interface, Django e Django REST Framework no backend, PostgreSQL no banco, Git no versionamento, Vercel no frontend e Render no backend e banco.

A fundação técnica está pronta, mas o sistema ainda não está completo para demonstração. O backend possui modelos, migrations, API CRUD, autenticação JWT e permissões iniciais. O frontend possui apenas a estrutura Vite/React e ainda não contém as telas do sistema.

Observação de segurança

O documento acadêmico define a data de nascimento como senha inicial. Essa senha é previsível. Caso a regra seja mantida para aderência ao trabalho, a troca no primeiro acesso deverá ser obrigatória. Nenhuma senha, token, chave ou arquivo .env real deverá ser enviado ao Git ou incluído no ZIP.

Roteiro recomendado

  1. Adequar a modelagem. Corrigir campos, status e relacionamentos antes de construir telas.
  2. Gerar e validar migrations. Executar toda a estrutura no PostgreSQL local.
  3. Implementar serviços de domínio. Orçamento, OS, estoque, requisições e primeiro acesso.
  4. Corrigir API e permissões. Garantir acesso por perfil e propriedade.
  5. Criar testes do backend. Validar regras e cenários críticos.
  6. Construir o frontend. Seguir os protótipos e integrar com a API.
  7. Testar o fluxo completo. Login, atendimento, aprovação, execução, estoque e histórico.
  8. Preparar demonstração. Criar contas, motocicletas, OS e peças fictícias.
  9. Publicar. Frontend na Vercel; backend e PostgreSQL na Render.
  10. Finalizar a entrega. Atualizar documentação e gerar ZIP sem segredos ou dependências instaladas.

Critérios para considerar o projeto pronto

  • Os quatro perfis conseguem entrar e enxergam somente as funções permitidas.
  • Um atendimento completo pode ser realizado do cadastro até a conclusão da OS.
  • O cliente consegue acompanhar sua OS e decidir o orçamento.
  • Peças utilizadas atualizam corretamente o estoque.
  • O histórico permanece vinculado à motocicleta.
  • Fotografias e registros de entrada podem ser consultados posteriormente.
  • O sistema funciona em computador e celular.
  • Frontend, API e PostgreSQL estão publicados e comunicando-se.
  • README e ZIP permitem que outra pessoa prepare o ambiente local.
  • Nenhuma credencial sensível está presente no repositório ou no ZIP.
